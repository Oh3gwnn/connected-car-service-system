# CAN 통신 가이드

이 문서는 실제 차량 환경(CANoe 및 다양한 CAN 버스 도메인, 물리 계층)을 소프트웨어적으로 가상화하는 전략을 정리한 가이드라인입니다.

---

### 1. python-can 라이브러리 vs Linux SocketCAN의 관계

가장 혼동하기 쉬운 개념인 파이썬 라이브러리와 리눅스 시스템 드라이버의 차이 및 연동 원리입니다.

**① 역할 분담 구조 (레이어 아키텍처)**

두 기술은 상하관계로 엮여 있으며, 실제 데이터의 흐름은 다음과 같습니다.

```
+-------------------------------------------------------------+
| 1. 파이썬 어플리케이션 영역 (우리가 작성하는 ccu.py 코드)              |
|    - "시동 제어 패킷을 vcan0으로 송신해라!"                        |
+----------------------------------------------+--------------+
                                    | (파이썬 코드 호출)
                                    ▼
+-------------------------------------------------------------+
| 2. python-can 라이브러리 영역                                   |
|    - 파이썬 코드를 리눅스 커널이 이해할 수 있는 시스템 콜로 변환          |
+----------------------------------------------+--------------+
                                   | (Socket API 호출: PF_CAN)
                                   ▼
+-------------------------------------------------------------+
| 3. 리눅스 커널 영역 (SocketCAN Subsystem)                       |
|    - 리눅스 운영체제가 메모리 상에 띄워둔 가상 네트워크 카드              |
|    - vcan0 인터페이스 관리 및 메시지 브로드캐스팅                     |
+-------------------------------------------------------------+
```

**② 상세 비교 및 비유**

**Linux SocketCAN (하부 인프라 - 도로 역할):**

리눅스 커널(OS) 자체에 포함된 네트워크 소켓 프로토콜 계층입니다.

가상 CAN 인터페이스(vcan0)를 일반 LAN선이나 와이파이 장치처럼 네트워크 기기로 등록해 패킷이 흐를 수 있도록 돕습니다.

**python-can (상부 애플리케이션 - 자동차 역할):**

파이썬 환경에서 제공되는 패키지 라이브러리입니다.

복잡한 C언어 소켓 프로그래밍을 할 필요 없이, can.Message() 형태로 직관적인 객체지향형 코드를 작성해 패킷을 생성하고 리눅스 도로(vcan0) 위로 전송할 수 있게 돕는 어댑터 래퍼(Wrapper)입니다.

### 2. 차량 내부 CAN 통신망의 구조 (도메인별 상세 약어)

실제 차 안에는 수십 개에서 백여 개에 달하는 제어기(ECU)가 엉켜 있습니다. 이를 기능적 목적과 물리적 속도 요구사항에 따라 여러 종류의 CAN 버스(도메인)로 분리하여 관리합니다.

- **B-CAN (Body CAN - 바디 캔):**

    주요 기능: 도어 잠금/열림, 원격 시동, 공조기(에어컨/히터) 제어, 창문 제어, 아웃사이드 미러 등 편의 장치를 담당합니다.

    특징: 고장 나더라도 주행 및 안전에 직접적인 치명타를 주지 않으므로, 비용이 저렴한 저속(Low-speed, 125kbps 이하) CAN 규격을 주로 사용합니다.

- **P-CAN (Powertrain CAN - 파워트레인 캔):**

    주요 기능: 엔진 제어기(ECU), 변속기 제어기(TCU), 가속 페달 센서 등 자동차를 움직이게 하는 심장부 제어입니다.

    특징: 극도로 신속하고 안정적인 실시간 반응이 필수적이므로 고속(High-speed, 500kbps) CAN 규격을 사용합니다.

- **C-CAN (Chassis CAN - 샤시 캔):**

    주요 기능: 미끄럼 방지 장치(ESC/ABS), 전자식 조향 장치(MDPS), 에어백 등 하체 현가/조향/제동 장치 제어입니다.

    특징: 운전자의 생명과 직결되므로 고속 통신과 함께 가장 높은 전송 우선순위 및 이중화 설계를 가집니다.

- **D-CAN (Diagnostic CAN - 진단 캔):**

    주요 기능: 차량 정비소에 가서 차량 하단 OBD-II 포트에 진단 장비(GDS 등)를 꽂아 고장 코드(DTC)를 읽거나 제어기 소프트웨어를 업데이트(ROM Write)할 때 쓰는 채널입니다.

- **E-CAN (Extended/Event CAN - 확장/하이브리드 제어 캔):**

    주요 기능: ADAS(첨단 운전자 보조 시스템) 레이더, 모빌리티 제어, 혹은 친환경차(HEV/EV)의 고전압 배터리 및 전기모터 간 하이브리드 제어 통신망입니다.

- **M-CAN (Multimedia CAN - 멀티미디어 캔):**

    주요 기능: AVN(오디오, 비디오, 내비게이션), 디지털 계기판(Cluster), 인포테인먼트 헤드 유닛 간 데이터 통신입니다.

### 3. 현 프로젝트에서 구현할 구체적 범위 (Scope)

고가의 Vector 장비(CANoe)와 실제 차량 제어기 하드웨어가 없는 한계를 극복하기 위해, 우리는 소프트웨어 기반의 논리적 에뮬레이션을 수행합니다.

B-CAN과 P-CAN 2가지 채널을 가상화하여, 중앙 게이트웨이(CGW) 기반의 데이터 중계 흐름을 그대로 재현합니다.

```
  [모바일 앱 / Swagger]
            │ (HTTP 요청)
            ▼
     [FastAPI 서버]
            │ (MQTT 무선 메시지 발행)
            ▼
     [가상 CCU 모듈] ─── (물리 채널 통과)
            │ 
            ├─► B-CAN (vcan0) 채널에 원격 시동 패킷 쏘기 (0x123 ID)
            │
     [가상 바디 제어기 (BCM)] (B-CAN 버스 상주)
            │ (0x123 수신 후 시동 시퀀스 판단)
            ├─► P-CAN (vcan1) 채널로 엔진 런 신호 릴레이 (0x200 ID)
            ▼
     [가상 엔진 제어기 (EMS)] (P-CAN 버스 상주)
              (실제 엔진 속도 2500 RPM 상승 연출 및 피드백)
```
